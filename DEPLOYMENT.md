# Deployment — getting a live link to share

The assignment PDF asks for a **GitHub repository link**. This document covers the
extra step of putting the API on a public URL as well, because a live link was
requested.

Target host: **Render** (Docker + managed PostgreSQL with pgvector, free tier).

---

## What you will end up sharing

Two links. Send both:

| Link | Example | Why |
|---|---|---|
| GitHub repository | `https://github.com/<username>/fastapi-rag-backend` | Required by the assignment |
| Live API docs | `https://fastapi-rag-backend.onrender.com/docs` | The deployment link — Swagger UI, every endpoint testable in the browser |

Send `/docs`, not the bare domain. The root `/` returns a small JSON blob; `/docs`
is the interactive Swagger UI where a reviewer can sign up, ingest a document and
call `/chat` without touching curl.

```powershell

git push -u origin main
```

Create the repo at https://github.com/new **empty** — no README, no .gitignore, no
license, otherwise the first push is rejected.

If the push asks for a password, use a **Personal Access Token** (Settings →
Developer settings → Personal access tokens → Tokens (classic), `repo` scope).

## Step 2 — Deploy on Render

`render.yaml` in the repo root already defines the web service *and* the database,
so this is mostly clicking through.

1. https://dashboard.render.com → **New +** → **Blueprint**
2. Connect your GitHub account, pick the repository you just pushed
3. Render reads `render.yaml` and shows two resources:
   - `fastapi-rag-backend` (web service, Docker)
   - `rag-postgres` (PostgreSQL 16, free)
4. It prompts for **`ANTHROPIC_API_KEY`** — paste your key, or leave it blank
   (ingestion and retrieval still work; only LLM answering needs it)
5. **Apply** / **Create Resources**

First build takes roughly 5–10 minutes.

`DATABASE_URL` and `JWT_SECRET_KEY` are wired automatically — the database URL comes
from the managed Postgres, and the JWT secret is randomly generated by Render. Do not
set them by hand.

## Step 3 — Enable pgvector

The app runs `CREATE EXTENSION IF NOT EXISTS vector` on startup
(`app/db/init_db.py:20`), which normally just works on Render.

If the deploy log shows `extension "vector" is not available` or a permissions error,
open the database in the Render dashboard → **Connect** → **PSQL command**, run it in
your terminal, and execute:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Then hit **Manual Deploy → Deploy latest commit** on the web service.

## Step 4 — Verify before sending the link

Replace `<app>` with your actual Render subdomain:

```bash
# Should return {"status":"ok",...}
curl https://<app>.onrender.com/health

# Full smoke test
BASE=https://<app>.onrender.com

TOKEN=$(curl -s -X POST $BASE/auth/signup \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"supersecret123"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

curl -s -X POST $BASE/documents \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"title":"France","text":"Paris is the capital of France. The Eiffel Tower is located in Paris."}'

sleep 3

curl -s -X POST $BASE/chat \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"query":"What is the capital of France?"}'
```

Checklist before you send anything:

- [ ] `/health` returns 200
- [ ] `/docs` loads in a browser
- [ ] Signup returns an `access_token`
- [ ] Document ingest returns a document id, and `/documents/{id}/status` reaches `completed`
- [ ] `/chat` returns an answer with `sources` (needs `ANTHROPIC_API_KEY`)

## Free-tier caveats — mention these to the reviewer

- **Cold starts.** The service sleeps after 15 minutes idle; the first request then
  takes ~50 seconds. Nothing is broken — it is waking up.
- **Database expiry.** Render's free PostgreSQL is deleted after 30 days. If the
  review happens later than that, redeploy or upgrade the database plan.
- **Redis is not deployed.** The cache layer degrades gracefully, so `/chat` still
  works — it just does not cache. Add a Render Key Value instance and set `REDIS_URL`
  if you want caching live.
- **Kafka is not deployed.** `INGEST_MODE=background` uses FastAPI BackgroundTasks
  instead. The Kafka path is demonstrable locally via
  `docker compose --profile kafka up`.

## Changes that were needed to make this deployable

Two things in the codebase would have broken a managed deploy:

1. **`Dockerfile:26`** hardcoded `--port 8000`. Render (and Railway, Cloud Run) inject
   a `$PORT` and ignore `EXPOSE`; a fixed port means health checks never pass. Now uses
   shell form with `${PORT:-8000}`, so local `docker compose` behaviour is unchanged.
2. **`app/core/config.py`** now normalises `DATABASE_URL`. Managed hosts hand out
   `postgres://…` or `postgresql://…?sslmode=require`; SQLAlchemy needs the
   `postgresql+asyncpg://` driver prefix, and asyncpg rejects libpq's `sslmode` /
   `channel_binding` parameters. The validator rewrites the prefix, maps
   `sslmode` → `ssl`, and drops `channel_binding`.

## Alternative hosts

The same `Dockerfile` works elsewhere; only the database wiring differs.

- **Railway** — deploy from repo, add the PostgreSQL plugin, then run
  `CREATE EXTENSION vector;` and set `DATABASE_URL` to the provided URL.
- **Fly.io** — `fly launch` (detects the Dockerfile), `fly postgres create`,
  `fly postgres attach`. Set `internal_port` to match `$PORT`.
- **Any VPS** — clone the repo, add `.env`, `docker compose up -d`, put nginx or
  Caddy in front for TLS. This is the only option that also runs Redis and Kafka.
